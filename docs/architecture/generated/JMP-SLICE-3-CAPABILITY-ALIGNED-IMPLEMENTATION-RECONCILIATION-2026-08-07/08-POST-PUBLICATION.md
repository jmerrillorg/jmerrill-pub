# Post-Publication Operations

Post-publication work must be first-class before runtime activation. Release is not the end of the publishing lifecycle.

| Work area | Authority / candidate system | Current status | Reconciliation decision |
| --- | --- | --- | --- |
| Royalties | Dataverse royalty statement/line authority plus BC payable/payment/GL | PARTIAL | Extend royalty proof into governed statement/payment sequence after authority. |
| Statements | Dataverse operational statement | PARTIAL | Generate/review/deliver after statement authority and author-facing policy are approved. |
| Author-copy orders | Author copy policy and package addenda | PARTIAL | Track entitlement/order/paid copies and avoid silent regeneration of executed agreements. |
| Complimentary entitlements | PUB-STD Author Copy Policy | BUILT | Keep as first-class policy and projection into fulfillment. |
| Annual distribution fees | Catalog/policy; BC candidate | PARTIAL | Integrate recurring fee, suspension/restoration, and payment status before runtime. |
| Corrections | CORRECTION_AUTHORIZED design | PARTIAL | Use Microsoft approvals/Dataverse audit first, custom only for publishing rules. |
| Revised editions | Target Architecture / title edition model | PARTIAL | Requires title/edition authority and no slot swapping. |
| Companion Editions | Open governed hold | MISSING | Do not implement affected runtime until companion model is ruled. |
| Title retirement | Operating Manual / MISSING row | MISSING | Needs governed manual-to-system path before automation. |
| Reversion | Operating Manual / MISSING row | MISSING | Needs legal/business decision path; no automated reversion. |
| Ongoing distribution | Release/distribution evidence | PARTIAL | Track live/readback/exceptions beyond initial launch. |
| Ongoing strategic marketing | Marketing register/future annual review | PARTIAL | Lifecycle marketing continues after live; should not stop at launch. |
