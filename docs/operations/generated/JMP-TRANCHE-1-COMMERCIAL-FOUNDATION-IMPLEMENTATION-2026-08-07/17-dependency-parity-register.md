## Environment Strategy Decision

JM1-Dev remains the correct named development candidate, but it cannot be brought to safe parity in this pass without either installing broad first-party applications not required for Tranche 1 or importing JM1 Active-layer prerequisites whose governed source packages are not present in this repository.

JM1-Test does not solve the problem. Its solution list is smaller than JM1-Dev and does not contain `JM1PublishingSales` or the missing Active-layer prerequisite set.

Decision: `DEVELOPMENT_SANDBOX_REQUIRED` unless Jackie separately authorizes a governed prerequisite-package recovery/import path for JM1-Dev. Tranche 1 runtime implementation remains stopped.

## Microsoft Dependency Finding

PAC reports many Microsoft first-party dependencies as resolvable from AppSource, and the JM1-Dev application catalog was captured. No Microsoft application was installed. The only Microsoft dependencies that look directly aligned to Tranche 1 are Sales, Lead Management, and Product Management. Field Service, Service Scheduling, Sales Insights, Accelerated Sales, Marketing/CXP, Power Pages, Omnichannel, Business Central integration, and similar dependencies are import drag from the current production-export boundary, not authorized Tranche 1 scope.

## JM1 Dependency Finding

The import failure includes 38 unique `Active` solution dependencies for JM1 tables/choices/fields. No current governed source package for those Active-layer prerequisites was found in this repository beyond the existing JM1PublishingSales package and an unrelated PAM baseline zip. These must not be recreated by copying isolated production components.

## Business Process Flow

The `jm1pub_publishingopportunityprocess` BPF entity and workflow are present in the source-controlled `JM1PublishingSales` boundary after the production solution-boundary repair. Current stage labels in source are: Discovery, Submission, Editorial Review, Package & Quote, Contract, Activation. The BPF should remain in `JM1PublishingSales`, but its import cannot be proven until required Sales and JM1 prerequisites are present or the solution boundary is rebuilt cleanly in DEV.
